01.

摘要與核心安全性保證 (Executive Summary)

HiddenData 是專為在桌面瀏覽器（Chrome 擴充功能側邊欄）及 Android 行動系統中，安全串流高畫質圖片、動態 GIF 與 4K 超高畫質影片所打造的企業級零知識 (Zero-Knowledge) 媒體保險箱。

傳統檔案加密工具或手機金庫 App 在開啟媒體時，會將完整檔案解密並寫入作業系統暫存目錄（如 /tmp、AppData/Local/Temp 或內部 App 快取）。HiddenData 徹底消除了磁碟寫入。所有解密均純粹在系統記憶體 (RAM) 中隨選即時完成，關閉視窗時立即觸發密碼學記憶體抹除 (Zeroization)。

零知識 (Zero-Knowledge) 絕對公理

無論是軟體開發者、Google Drive 雲端伺服器或任何中間網路實體，均無法接觸使用者的主密碼、衍生金鑰或明文檔案。若使用者遺忘主密碼，在數學原理上絕無任何還原可能。本系統絕不存在任何託管金鑰或後門程序。

02.

密碼學原語與金鑰衍生規格

所有加密運算均嚴格遵循美國國家標準暨技術研究院 (NIST) 建議標準與現代認證加密 (AEAD) 規範。

密碼學參數 標準規範與實作方式 安全性目的與依據
對稱金鑰演算法 AES-256-GCM (NoPadding) Galois/Counter Mode 提供硬體加速的高速機密性與 128 位元完整性認證 (AEAD)。
金鑰長度 256-bit (32 bytes) 採用最高規格 256 位元金鑰，能抵禦量子電腦 Grover 演算法攻擊（等效 128 位元量子安全性）。
金鑰衍生函數 (KDF) PBKDF2-HMAC-SHA256 將使用者密碼延伸為 256 位元金鑰加密金鑰 (KEK)，阻絕 GPU/ASIC 彩虹表預計算攻擊。
KDF 運算工作量 (迭代次數) 100,000 iterations 100,000 次反覆運算對暴力破解施加極大計算成本，同時將本地端解鎖時間維持在 250 毫秒以內。
鹽值 (Salt) 生成 16-byte CSPRNG 透過密碼學安全隨機數生成器 (crypto.getRandomValues / SecureRandom) 為每個檔案生成獨立 16 位元組鹽值。
區塊 AEAD 隨機數 (Nonce) 96-bit (Base IV ⊕ Chunk Index) 以 12 位元組 Base IV 結合 64 位元區塊計數器進行 XOR 運算，杜絕 Nonce 重用與區塊重排/調換攻擊。
即時金鑰驗證碼 (Key Verifier) 16-byte SHA-256 Digest 無需耗時解密大容量內容，0.001 秒即可瞬間確認主密碼是否正確。
授權防偽數位簽章 HMAC-SHA256 (V2 Protocol) 無需中央帳號伺服器，透過 HMAC-SHA256 數位簽章在 Android 與電腦端安全同步 Pro 授權。
額外認證資料 (AAD) 綁定防竄改保護

為防止攻擊者在不同加密檔案之間剪貼置換區塊，HiddenData 將檔案封套標頭的前 32 位元組作為額外認證資料 (AAD) 帶入每個 64KB 區塊加密運算中。一旦區塊順序或來源遭竄改，GCM 驗證標籤將立刻報錯阻擋。

03.

零磁碟 (Zero-Disk) 記憶體即時串流架構

傳統檔案加密工具依賴「解密至磁碟」模式：當使用者點擊加密影片時，工具會在暫存目錄產生明文檔案並呼叫系統播放器，於視窗關閉時嘗試刪除該檔案。

這種陳舊的架構會產生極嚴重的隱私漏洞：

  • 磁碟鑑識殘留：即使檔案被刪除，快閃記憶體或硬碟的未配置區塊仍保留原始資料，可被 EnCase、FTK 等數位鑑識軟體輕易復原。
  • 作業系統縮圖與歷程紀錄：Windows Shell 或 macOS Spotlight 會自動為暫存目錄編制索引，留下未加密的縮圖快取與 Shellbag 軌跡。
  • 程式崩潰導致明文殘留：若播放過程異常當機或突然斷電，已解密的明文檔案將永遠暴露在磁碟中。

HiddenData 零磁碟解決方案：Android App 與 Chrome 側邊欄均採用純記憶體串流管道：

播放 4K 60fps 影片時，HiddenData 透過位元組範圍請求以 64KB 區塊逐步獲取資料。每個區塊在記憶體 (RAM) 中驗證並解密後，直接輸送至瀏覽器的 MediaSource 緩衝區或 Android MediaCodec。使用者離開或關閉檢視器時，TypedArray 記憶體區塊會立即由 Arrays.fill(buffer, 0) 以 0 全數覆寫抹除。

KeySlotManager 與 0.001 秒不可分割金鑰更新

在傳統保險箱中，變更主密碼必須將數百 GB 的整個儲存庫解密再重新加密，耗費數小時磁碟 I/O，嚴重損耗 SSD 壽命並帶來斷電毀損風險。

HiddenData 透過 KeySlotManager 封套加密架構解決此難題。檔案內容由隨機產生的 256 位元主金鑰 (MK) 加密，而該 MK 則由使用者密碼衍生出的金鑰加密金鑰 (KEK) 加密並儲存於標頭中。

原子化金鑰更新效能：精確至 0.001 秒

當使用者更換密碼時，HiddenData 僅需以新 KEK 重新加密標頭內的 32 位元組主金鑰，完全無需觸動數 GB 的檔案內容主體。每個檔案在 1 毫秒內原子化完成更新，零資料毀損風險。

標頭內建 V3 縮圖區塊 (0.005 秒高速預覽)

為了在包含數千個加密檔案的保險庫中實現順暢的 60fps 瀏覽，V3 標頭中直接內嵌了 128x128 加密 WebP 縮圖。只需讀取檔案開頭約 2KB，即可在 0.005 秒內呈現預覽，相較傳統工具載入速度提升逾 200 倍。

05.

Google Drive 最小權限隔離 (drive.file 範圍)

在進行雲端備份時，許多第三方應用程式會索求 Google Drive 完整存取權限 (.../auth/drive)，導致其有權讀取或刪除使用者既有的所有個人文件與照片。

權限類別 OAuth 2.0 權限範圍 URI 授予之存取邊界 隱私風險評估
HiddenData 規範 .../auth/drive.file 僅限存取由 HiddenData 自行建立的加密檔案 (.enc) 與設定檔。對既有 Drive 內容存取權限為 0%。 通過 CASA 認證 / 零資安風險
一般保險箱 App .../auth/drive 對使用者 Google Drive 全碟檔案擁有不受限制的讀取、寫入與刪除權限。 嚴重隱私威脅

HiddenData 嚴格落實最小權限原則 (Least Privilege)：

  • 零存取個人檔案：HiddenData 無法檢視、搜尋或接觸使用者在 Google Drive 中原有的任何 Google Docs、試算表或照片。
  • 100% 密文儲存：儲存於 HiddenData_Vault 資料夾的所有檔案均已在本地完成高強度加密，Google 伺服器僅能看到隨機二進位區塊。
  • 無中介伺服器傳輸：使用者裝置與 Google 官方 REST API 透過 TLS 1.3 直接對接，絕無開發商代理伺服器經手資料。
06.

跨平台 Pro 授權防偽驗證協定

HiddenData 不設中央會員帳號資料庫。當使用者透過 Lemon Squeezy 購買 Pro 終身授權時，系統如何在無追蹤伺服器的情況下安全同步電腦與手機？

答案是 V2 數位簽章授權封套 (.hiddendata_pro_license.json)：

  • 購買完成時，付款 Webhook 會發布綁定使用者 Google 信箱與訂單編號的 HMAC-SHA256 數位簽章。
  • 該加密授權權杖會安全存放在使用者個人的 Google Drive 保險庫資料夾中。
  • 當 Android App 或 Chrome 擴充功能開啟時，會離線驗證該數位簽章，永久啟用雙平台 Pro 功能，無需後續週期性驗證。
